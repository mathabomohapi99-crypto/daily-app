# Sprint 1 Retrospective — CampusFlow

## What went well
- Writing full user stories (instead of raw backlog phrases) made the scope of each item much clearer before any code was written.
- The INVEST check on the persistence story caught a scope problem early, before time was wasted trying to build one oversized feature.

## What didn't go well
- Most Sprint 1 stories are still at To Do — only the board and a basic add-card flow are built, so the sprint's actual output is much smaller than the backlog suggested.
- Story sizing for "persist data" was underestimated on first look, because the backlog phrase hid how many other features it depended on.

## Concrete change for Sprint 2
Before pulling any story into a sprint, run it through the INVEST check as part of Definition of Ready — not after starting on it. This would catch oversized or dependent stories (like persistence) before they're already in progress.
